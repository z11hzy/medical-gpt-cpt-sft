# CPT 参数与两万条数据核验报告

日期：2026-09-05。范围：现有 CPT v1 配置、安装的上游及依赖代码、20,000 条候选训练文本、500 条官方验证文本、C-Eval 医学三科 val 共 90 题。

本次只运行审计程序、读取数据并生成报告；未训练模型，未修改训练配置、训练数据或模型权重。可复现程序见 tools/audit_cpt.py，原始统计见 [cpt-audit.json](results/cpt-audit.json)。

## 结论

两万条数据在本机具备完整训练的条件，按当前分块方式约有 745 万 token，预计约一小时。建议先修复参数兼容问题，并处理重复与可疑数据，再开始完整训练。

已确认两个参数被静默忽略；数据格式正常，但存在完全重复、跨集合近重复和明显乱码。尚未对全部文本完成医学事实审查，不能称为高质量医学语料。

## 1. 参数核验

| 设置 | 实际结果 | 下一轮建议 |
| --- | --- | --- |
| warmup_ratio=0.05 | 未识别，被丢弃；实际 warmup_steps=0 | 使用当前版本支持的 warmup_steps |
| overwrite_output_dir | 未识别，被丢弃 | 不依赖该参数；每次使用新实验目录 |
| max_train_samples=4000 | 对分词拼接后的块截断 | 完整训练需去掉该限制 |
| max_eval_samples=500 | 只评测前 500 块 | 去掉限制，评测全部 717 块 |
| batch=2，梯度累积=4 | 有效 batch=8 | 当前配置已跑通，可作为下一轮起点 |
| LoRA rank=8、alpha=16、dropout=0.05 | 与适配器配置一致 | 当前无需因兼容性修改 |
| BF16 | 已生效 | 保留 |
| 梯度检查点 | v1 为关闭状态 | 保留已验证配置，必要时按显存调整 |
| 优化器 | AdamW Torch Fused | 已被当前版本识别 |

根因在 MedicalGPT 的 training/pretraining.py 第 354 行附近：解析时设置 return_remaining_strings=True，然后只保留前四个返回对象，未检查未识别参数。未知参数不会报错。

安装的 Transformers training_args.py 已无 warmup_ratio 字段。get_warmup_steps 根据 warmup_steps 计算预热：大于等于 1 时按步数，小于 1 时按比例。本次复用相同解析器，确认剩余参数为 warmup_ratio、0.05 和 overwrite_output_dir；实际预热为 0。此前将 5% 预热写成已生效配置是不准确的。

建议下一轮严格检查未知参数；若清洗后步数仍为 3,638，5% 预热可明确设为 warmup_steps=182。数据清洗后需重新统计再确定步数。本次未应用修复。

## 2. 完整数据规模

| 项目 | 训练子集 | 官方验证集 |
| --- | ---: | ---: |
| 原始记录数 | 20,000 | 500 |
| 分词 token 数，不含补入的 EOS | 7,431,446 | 183,289 |
| 拼接后的 256-token 块 | 29,097 | 717 |
| 可输入的 token 数 | 7,448,832 | 183,552 |
| 分块丢弃的尾部 token | 2,614 | 237 |
| 上一轮实际使用块数 | 4,000 | 500 |
| 上一轮涉及原文数 | 2,721 | 336 |

涉及原文包含被部分使用的边界文档，不等于完整使用了这些文档。统计复现上游每批 1,000 篇拼接和丢弃尾部的行为，采用同一本地分词器。

训练原文 token 长度：中位数 417，P95 为 573，最长 8,233。256-token 分块会切开多数较长文档，后续片段无法看到前一块的上下文；除各批尾部外，并不是将长文档一律截断丢掉。是否增加上下文长度应另做显存、速度和效果对照。

按有效 batch=8，当前未清洗数据全量一轮约为 3,638 步，是上一轮输入规模的 7.27 倍。根据 433.06 秒实测线性外推约 52.5 分钟，可预留 50–70 分钟；这是估算，实际还受温度、负载、验证和保存频率影响，不能保证。

## 3. 重复与污染检查

| 检查 | 结果 | 解释 |
| --- | --- | --- |
| JSON 和非空文本字段 | 训练、验证均无错误 | 格式可以读入，不等于内容可靠 |
| 训练内部完全重复 | 76 组，多余记录 84 条，约 0.42% | 去重后剩 19,916 条 |
| 训练内部高相似度 | 19 对非完全重复候选 | 仍需逐对复核，不是自动删除名单 |
| 训练与验证完全重复 | 未发现 | 使用 NFKC、去标点空白后的文本匹配 |
| 训练与验证高相似度 | 2 对 | 已查看内容，存在明显共享段落 |
| C-Eval 题干字面命中 | 1 个短语命中 | 仅四字甲肝感染，不能判定泄题 |

两对跨集合近重复，行号从 1 开始：

- 验证第 233 行与训练第 13,707 行：女性尿频尿急尿痛主题，余弦相似度约 0.9898。
- 验证第 399 行与训练第 12,313 行：腹胀病因/发病机制主题，余弦相似度约 0.9760。

对应训练文本均未进入 v1 的前 4,000 块，因此不能据此指认上一轮 PPL 改善源于这两对污染。但完整训练两万条前应处理它们，优先保留验证集，将重合训练文本排除或按来源重新组织切分。

相似度方法为字符 3/4-gram、2^20 桶哈希 TF-IDF、余弦阈值 0.95；训练内部只查最近两个邻居。这是有限召回的候选检测，不保证找全所有近重复、同义改写或语义泄漏。

初次使用前 50,000 个常见特征时，短文本模板导致大量假阳性；抽查后已改用保留稀有词特征的哈希方案重算。最终采用本报告和 JSON 中的 19 对及 2 对结果。

C-Eval 医师 id=34 的短题干是甲肝感染，训练第 2,276 行在疾病介绍中包含该短语，未据此确认整题及答案复制。未发现其余题干的标准化完整子串命中；该结果不能排除改写污染，也无法追溯基模预训练数据。

## 4. 内容质量抽查

| 检查 | 数量 | 含义 |
| --- | ---: | --- |
| 含 Unicode 替换符的文本 | 1 条 | 训练第 6,754 行，查看后确认存在明显乱码 |
| 少于 20 个字符 | 95 条 | 需要区分短而有效的定义与低信息文本 |
| 命中根治、无副作用等筛查词 | 544 条 | 含否定语境，不能当成 544 条错误文本 |
| 命中偏方、秘方、祖传 | 65 条 | 有些明确反对偏方，需要上下文判断 |
| 含 URL | 7 条 | 待检查来源及正文噪声 |
| 命中指定推广或手机号模式 | 0 条 | 规则有限，不代表完成隐私和广告审查 |

定向抽查发现第 38 行有完全治愈、不复发的笼统承诺；第 1,073 行包含偏方推荐。固定 seed=42 随机抽查 12 条的开头，还发现人物生平、植物分类等内容，以及第 8,025 行中明显不自然的词语替换。这些记录应进入人工复核，而不能把整个语料都当作一致质量的医学教材。

此前续写中高血压与不孕的不可靠关联，尚未定位其确切来源。两者在 100 字范围内共同出现的训练记录有 14 条，但共现不等于相同错误结论，更不能证明因果来源。

本轮是工程与文本质量审计，未逐条核对医学指南，未统计经专业确认的医学错误率。测试文件未参与模型评测，本次也未扩展对它的内容审查。

## 5. 对已有结果的影响与下一步

既有 Loss/PPL 和 C-Eval 原始数值无需凭本次审计改写。但它们应描述为零预热、部分训练块、部分验证块上的小规模实验结果。尚不具备宣称全量训练、充分去重或医学能力稳定提升的条件。

建议顺序：

1. 修正预热和未知参数检查，改用新实验输出目录。
2. 删除已确认的精确重复多余记录，隔离乱码，处理两对跨集合近重复。
3. 对高相似度和内容质量候选人工复核，不能按关键词整批删除。
4. 固定清洗后数据版本并重新统计 token、优化步数和预热。
5. Base 与完整 CPT 使用同一完整验证集对比，并保留相同 C-Eval 方法及续写案例。

以上是建议，尚未执行；本次没有扩大训练或清洗原数据。
