# SFT 数据审计与 2 万条子集报告

日期：2026-09-05。范围：`shibing624/medical` 中文 SFT 训练集 1,949,972 条、官方 validation 500 条、官方 test 500 条，以及本项目已固定的 CPT 训练文本和 C-Eval 医学 90 题。

本轮完成数据下载后的全量流式审计、确定性抽样、格式转换和近重复筛查，未启动 SFT。最终候选数据位于 `data/processed/sft-clean-20k-v2`，可复现脚本为 `data_pipeline/prepare_sft_subset.py`，机器可读报告为 `reports/results/sft-audit-v2.json`。

## 结论

已生成可由 MedicalGPT 直接加载的 20,000 条 ShareGPT 格式候选集。抽样前自动排除格式/编码异常、标准化完全重复、与官方留出问题重合、与本次 CPT 训练问答完全重合，以及 URL、联系方式和已人工确认的问题样本。Base 与 CPT 后续必须使用这一份完全相同的数据和顺序。

这是一份工程清洗后的实验数据，不是经医生逐条认证的临床语料。关键词筛查仍命中一些需要后续抽查的记录，因此不得把它描述成“医学事实完全可靠”。

## 3. 子集生成规则

在通过客观排除条件的记录中，计算 `SHA-256(seed + canonical JSON)`，选择哈希值最低的 20,000 条，seed 为 42。该方法与源文件顺序无关并可重复得到相同结果；它是确定性抽样，不是质量评分。

输出统一转换为：

```json
{"conversations":[{"from":"human","value":"医学问题"},{"from":"gpt","value":"医学回答"}]}
```

MedicalGPT 实际加载器验证通过：train 20,000 条、validation 500 条。官方 test 500 条也已转换并单独保留。

## 4. 近重复与剩余风险

最终子集使用字符 3/4-gram 哈希 TF-IDF、余弦相似度不低于 0.97 的有限召回筛查。训练内部候选为 0，训练与 validation/test 候选也为 0。该结果不能排除低于阈值的改写、语义重复或基模预训练污染。

最终 20,000 条仍有：

- 318 条命中根治、百分百、无副作用等宽泛筛查词；其中可能包含“无法根治”等否定语境。
- 78 条命中偏方、秘方或祖传；其中可能包含反对偏方的回答。
- 4,817 条回答少于 10 个字符，多数来自知识图谱式短答案，不能仅因短而删除。
- 11 条回答超过 4,000 字符，使用 512-token 上限时会被截断。
- 3 组相同问题对应不同答案，没有完全相同回答；作为多答案监督保留并列为限制。

URL、推广联系方式、手机号和 U+FFFD 在最终子集中均为 0。终端曾因 Windows 输出编码显示乱码；按底层 Unicode 码点复核后，相关样本实际为正常中文，不是文件编码损坏。

## 5. SFT token 与训练计划

统计严格复现 Qwen 聊天模板和 MedicalGPT 的按比例截断逻辑，最大长度为 512，并只对 assistant 回答计算训练损失。

| 项目 | 训练集 |
| --- | ---: |
| 模板化并截断后的输入 token | 3,091,741 |
| 参与 loss 的 assistant token | 2,224,939 |
| 中位输入长度 | 119 token |
| P90 / P95 输入长度 | 437 / 496 token |
| 发生截断 | 778 条，3.89% |
| 有效 batch | 4（每卡 1 × 梯度累积 4） |
| 1 epoch 更新步数 | 5,000 |
| 5% warmup | 250 step |

旧 SFT smoke 配置仍指向旧模型，并使用可能被静默忽略的 warmup_ratio。正式训练前需要改为本次完整 CPT 权重、固定 v2 数据哈希、明确 warmup_steps=250，并增加未知参数拒绝检查。建议先跑 1,000 条冒烟测试，再运行 Base→SFT 与 CPT→SFT 两个受控分支。
