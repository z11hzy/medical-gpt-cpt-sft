# MedicalGPT 项目最终实验报告

## 1. 项目目标

以 Qwen2.5 为基座，完成中文医疗领域的继续预训练（CPT/PT）、监督微调（SFT）和偏好/强化学习后训练（DPO、PPO、GRPO），并使用独立测试集与 C-Eval 医学题进行验证。

## 2. 数据与训练链路

```text
医疗原始数据
  ├─ 清洗后的医学文本 ──> CPT/PT
  └─ 医疗问答 ──────────> SFT
                              ├─ DPO
                              ├─ Reward Model
                              └─ GRPO / PPO
```

- CPT：从医学文本中构造 20k 子集，清洗、去重并记录 SHA-256。
- SFT：固定 20k 医疗问答训练集，保留 500 条验证集和 500 条测试集。
- DPO：从中文偏好数据中筛选 6,055 对可用样本，训练 7B SFT 后的偏好适配器。
- PPO/GRPO：使用 0.5B Reward Model 验证 RLHF 工程链路；GRPO 在 7B SFT 合并底座上使用 4-bit QLoRA。

## 3. 7B PT/CPT 与 SFT 结果

| 分支 | 验证 loss | 验证 PPL | 测试 loss | 测试 PPL | C-Eval 医学题 |
|---|---:|---:|---:|---:|---:|
| Base | 2.4796 | 11.9359 | 2.5017 | 12.2032 | 76/90 |
| CPT | 2.3600 | 10.5908 | 2.3879 | 10.8903 | 77/90 |
| Base → SFT | 2.0851 | 8.0457 | 2.1155 | 8.2940 | 75/90 |
| CPT → SFT | 2.0923 | 8.1037 | 2.1252 | 8.3748 | 78/90 |

CPT 明显改善了同分布医学文本的语言建模指标，但 CPT → SFT 相比 Base → SFT 的优势较小，C-Eval 差异也没有达到稳定显著的程度。

## 4. RLHF / GRPO 正式结果

### DPO（7B Base → SFT 后）

- 训练样本：5,555；验证样本：500。
- 训练 loss：0.5957；验证 loss：0.5637。
- 偏好准确率：0.742；平均 reward margin：0.4235。

### PPO（0.5B 工程验证）

完成了真实 PPO 训练链路：SFT policy、Reward Model、value model、KL 约束和 PPO 更新均正常运行。该实验用于验证工程可行性，不作为 7B 主结果。

### GRPO（7B 正式实验）

- 起点：7B CPT/SFT 合并底座。
- 训练：250 steps，每个问题生成 4 个候选，最大 128 tokens，4-bit QLoRA。
- 500 条独立开放式测试集上的自动奖励：

| 指标 | SFT | GRPO |
|---|---:|---:|
| 奖励模型均分 | 0.1596 | 0.0800 |
| 平均生成 token | 187.50 | 188.52 |
| EOS 正常结束率 | 83.6% | 83.0% |

- C-Eval：SFT `74/90 = 82.22%`，GRPO `74/90 = 82.22%`。

结论：GRPO 链路已跑通，但当前奖励模型和训练配置没有证明整体优于 SFT。自动奖励复用了训练奖励模型，不是独立医学裁判；因此不能把结果表述为医学准确率提升。

## 5. 当前结论

本项目最可靠的成果是完成了从数据处理、CPT/PT、SFT、偏好优化到 RLHF 评测的可复现实验链路，并保留了正式结果和局限性说明。下一步若继续优化，应先重构医学偏好数据、提升 Reward Model 的医学可靠性，再做 CoT SFT 冷启动和新一轮 GRPO。

## 6. 复现与限制

- 原始数据、模型权重、训练输出和中间 checkpoint 不进入公开仓库。
- C-Eval 使用公开医学 validation split 的 90 题，不等同于临床验证。
- PPL/loss 只能反映语言建模或监督目标，不能直接等同于医学安全性。
- 医疗模型不能替代医生进行诊断、处方或急救决策。
